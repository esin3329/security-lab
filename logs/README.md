# Logs (측정 로그 및 관찰 기록 보관소)

> 본 디렉터리는 보안 점검 도구 실행 결과, 지표 측정 로그, 환경 검증 메모를 보관하는 공간입니다.

## 1. 기록 원칙

- **JSONL Append-Only 보관:** 완결된 측정 결과는 `benchmarks/metrics.schema.json` 규격에 맞는 단일 줄 JSON 객체 형태로 파일 끝에 순차 추가(append-only)합니다.
- **실행 단위 식별:** 각 실행은 고유한 `run_id` (예: `YYYY-MM-DD-<target>-<tool>-<seq>`)를 부여하여 식별합니다.
- **완결된 1회 측정 = 1객체:** 대상 작업은 회당 15분(900초), 단일 타겟, 동일 조건 3회입니다. 준비·정리 포함 래퍼 시작~종료 시간은 실제 초로 기록합니다. 지표가 미완결이면 JSONL 대신 안전한 Markdown 관찰 메모를 남깁니다. 현재 Strix 래퍼는 dry-run만 제공하며 자동 로그 저장은 미구현입니다.

## 2. 측정 계약의 기록 항목

스키마 필수 항목은 `run_id`, `timestamp`, `tool`, `tool_version`, `target`, `metrics`입니다. 아래 시간·반복 정책은 별도 확인이 필요하고, `notes`는 선택 항목입니다.

1. `run_id`: 실행 고유 식별자
2. `timestamp`: UTC 기준 실행 시작 일시
3. `tool`, `tool_version`: 사용 도구명 및 고정된 버전 태그
4. `target`: 점검 대상 명칭 및 `host:port`
5. `time_limit_min`: 제한 시간 (15분 고정; 현재 스키마는 누락·다른 값을 차단하지 못함)
6. `repeat_index`: 반복 수행 번호 (1~3)
7. `metrics`: 8개 지표 (TP, FP, PoC 성공률, 소요 시간, 토큰/비용, 개입 횟수, 재현성, 설명가능성)
8. `notes`: 안전하고 간결한 한국어 요약 관찰 메모 (선택)

## 3. 보관 금지 및 보안 통제 항목

- **페이로드 및 익스플로잇 코드 저장 절대 금지:** 완성된 공격 코드, 쉘코드, 구체적인 악성 입력값을 로그에 남기지 않습니다.
- **원시 터미널 출력(stdout/stderr) 무차별 덤프 금지:** 비구조화된 대량 출력이나 불필요한 디버그 덤프를 저장하지 않습니다.
- **민감 정보 제외:** API 키, 토큰, 내부 계정 정보 등 비밀 정보가 로그 파일에 유입되지 않도록 통제합니다.

## 4. 결측치 및 판정 유보 처리 정책

- 확정된 ground-truth가 없거나 측정이 불가능했던 항목을 임의의 `0`으로 기록하지 않습니다.
- 미측정, 미시도, 판정 유보 항목은 Markdown 관찰 메모 또는 요약 보고서에 사유를 명시하여 실측 데이터와 구분합니다. 현재 스키마는 지표의 결측치 표현을 지원하지 않으므로 `notes`만으로 불완전한 객체를 완결 측정으로 인증할 수 없습니다.
- ground-truth의 빈 `findings`는 미확정 스텁이며 TP/FP 0건 판정에 사용하지 않습니다. 확정된 8지표가 없는 동안 완결된 JSONL 기록과 비교는 차단 상태입니다.
