# Targets (실습 대상 환경 안내)

> 본 디렉터리는 보안 실습 및 점검 대상 애플리케이션의 환경 정의와 구성 정보를 다룹니다.

## 1. 개요 및 역할

- `security-lab`의 로컬 보안 점검 대상 애플리케이션 정보를 정의하고 관리합니다.
- 외부 서버나 인가되지 않은 시스템에 대한 스캔을 원천 차단하며, 사전에 승인된 격리 환경 내 대상만 취급합니다.

## 2. MVP 대상 환경

- **단일 대상:** OWASP Juice Shop `v17.1.1` (`bkimminich/juice-shop:v17.1.1`)
- **네트워크 구성:** `infra/compose.targets.yml`에 정의된 `targets-net` (내부 격리 네트워크, `internal: true`)
- **허용 주소 (allowlist):**
  - 컨테이너 내부 통신: `juice-shop:3000`
  - 로컬 루프백 인터페이스: `127.0.0.1:3000`, `localhost:3000`

## 3. 실행 및 검증 절차

1. **로컬 준비:** 저장소 정적 설정 및 allowlist 파일(`tools/strix/targets.allow`) 무결성 확인.
2. **정적 확인:** 도구 실행 래퍼의 입력 검증 및 차단 규칙 점검.
3. **사용자 VM 검증:** 사용자의 격리된 로컬 Ubuntu VM 환경에서 컨테이너 기동 및 연결성 검증 (Windows 호스트에서의 직접 실행 금지).
4. **기록:** 점검 결과는 `logs/` 디렉터리에 표준 규격으로 기록.

## 4. Phase 2 제외 및 확장 예정 범위

- **MVP 제외:** WebGoat, 자작 취약점 테스트 API, 다중 타겟 환경 등은 MVP 범위에서 제외됩니다.
- **Phase 2 예고:** Juice Shop 기반의 단일 점검 체계 및 ground-truth가 안정화된 이후 다중 웹 애플리케이션 타겟으로 확장 예정입니다.

## 5. 보안 및 점검 원칙

- **외부 대상 스캔 절대 금지:** 지정된 로컬 격리망 외의 외부 IP 또는 도메인 점검을 엄격히 금지합니다.
- **페이로드 기재 금지:** 문서, 설정 및 결과 기록에 실제 악성 페이로드나 공격 코드를 포함하지 않습니다.
