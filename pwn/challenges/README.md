# Pwn 실습 환경 및 챌린지 안내 (로컬 바이너리 CTF 및 기초 pwn)

> 바이너리 보안 실습은 사용자가 허가받은 로컬 환경에서 다운로드/재현 가능한 문제를 다루며, 실제 flag 검증 receipt를 통해 판정합니다.

---

## 1. 실습 문제 구성 및 목표

- **주 실습 (플래그 획득 CTF):**
  - 다운로드 및 로컬 격리 컨테이너 내 재현이 허용된 flag-bearing 바이너리 문제를 대상으로 합니다.
  - 실제 flag code 확인 및 로컬 validator / 플랫폼 제출 receipt를 통해 성공 여부를 판정합니다.
- **기초 보조 문제 (Phoenix Stack Zero):**
  - 문제 링크: https://exploit.education/phoenix/stack-zero/
  - Phoenix Stack Zero는 GDB 및 pwndbg를 활용한 스택 버퍼 구조 및 메모리 변수 덮어쓰기 관찰용 기초 보조 문제입니다.
  - **주의:** Stack Zero의 성공 메시지는 기초 문제의 조건 충족이며 실제 CTF flag가 아닙니다. 임의의 플래그 획득으로 간주하지 않습니다.
- **보조 학습 플랫폼:**
  - **Dreamhack Wargame (https://dreamhack.io/wargame/):** 시스템 해킹/pwnable 기초 문제의 수동 실습 및 다운로드 보조.
  - **pwn.college (https://pwn.college/):** 시스템/바이너리 실습 환경. 공식 rules의 공개 writeup·솔루션 영상 제한을 지키고, 본 프로젝트 정책으로 실제 flag와 문제별 정답도 Git에 보관하지 않습니다.

---

## 2. 도구별 역할

- **GDB + pwndbg:** 바이너리 메모리 레이아웃, 레지스터 상태, 함수 프롤로그 및 실행 흐름 실시간 관찰.
- **pwntools (`==4.14.0`):** 승인된 로컬 챌린지 프로세스와의 입출력 상호작용 및 재현 절차 보조.
- **REA (후속 연동 예정):** 바이너리 디스어셈블리 및 MCP 기반 리버싱 분석 근거 도출.

---

## 3. 진행 절차 (4단계 순서)

1. **로컬 준비:** `pwn/Dockerfile` 정적 설정 확인 및 로컬 챌린지 파일 준비.
2. **정적/모의 확인:** Dockerfile 구성(Ubuntu 24.04, GDB, pwntools==4.14.0), pwndbg 2026.09.15 commit `55596aa676a2756efb8d67034f31675170eabe48` 고정(공식 commit/tags API 확인), legacy `setup.sh`의 `--yes` 미지원 옵션 제거 및 오류 전파 설정 정적 점검.
3. **사용자 VM 검증:** 사용자의 격리된 로컬 Ubuntu VM 환경에서 컨테이너 빌드 및 도구(`gdb + pwndbg`) 동작 확인 (현재 컨테이너 빌드/VM 실행은 **미실행**, Windows 호스트 빌드/실습 금지).
4. **기록:** 관찰 결과는 `pwn/exploits/`에 플래그 본문과 완성 공격 코드 없이 판정 receipt 및 한국어 관찰 메모로 기록.

---

## 4. 보안 및 실습 원칙

- **로컬 실행 원칙:** 모든 실습은 로컬 컨테이너 내부에서만 수행하며, 외부 서버 대상 원격 익스플로잇은 엄격히 금지합니다.
- **기밀 및 풀이 보관 금지:** 실제 획득한 플래그 문자열, 쉘코드, 완성된 익스플로잇, 문제별 정답 풀이는 저장소나 커밋에 포함하지 않습니다.
